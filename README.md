# Mconnect

本项目由AI辅助编程。

Mconnect 是一个 Flutter Android 音乐聚合应用，用同一套界面聚合网易云音乐、QQ 音乐和酷狗音乐的搜索、播放、歌词、歌单、收藏、下载和本地音乐能力。

> 说明：第三方音乐平台接口会变化，登录态、VIP 播放和高音质下载最终仍由平台服务端决定。本项目不保存任何真实账号凭据到仓库，运行时会话只保存在用户设备本地。

## 功能概览

- 多平台搜索：支持按歌曲或歌单搜索网易云、QQ 音乐和酷狗内容。
- 播放器：支持播放队列、上一首/下一首、迷你播放器、全屏播放器、进度记忆和音质选择。
- 歌词：支持 LRC/QRC/KRC 时间轴歌词，平台提供逐字或翻译歌词时会尽量同步展示。
- 音乐库：包含我喜欢、听歌历史、平台歌单、导入歌单、本地音乐和下载管理。
- 歌单：支持查看平台歌单、导入分享链接、创建和管理本地“我的歌单”。
- 本地音乐：支持选择目录扫描本地歌曲，并匹配同名歌词时间轴文件。
- 下载：支持下载队列、自定义下载目录、打开下载文件夹，并在删除下载记录时删除本地文件。
- 账号：每个平台独立登录和登出，登录会话通过 `flutter_secure_storage` 保存在本机。
- 主题色自选：支持多种预设主题色切换，设置即时生效并持久保存。
- 桌面悬浮歌词：支持开启 Android 悬浮窗歌词，可自定义歌词颜色、高亮颜色、字号、描边强度，支持拖拽移动和缩放。
- 听歌统计：新增本地听歌统计，记录总播放次数、累计听歌时长、最爱歌曲排行。
- 睡眠定时器：支持设置定时时长，倒计时结束后自动暂停播放。
- 淡入淡出：可选开关，切换歌曲时音量平滑过渡。
- 均衡器：支持 Android 原生均衡器，提供预设切换和五频段手动调节。
- 离线缓存中心：支持设置缓存大小上限、仅 Wi-Fi 缓存、自动清理等策略。
- 智能歌单：支持按平台、关键词、最低播放次数、最近播放、仅喜欢、仅缓存等规则自动生成本地歌单。
- 诊断：包含慢操作日志和 UI 卡顿监控，日志文件有大小上限，避免无限增长。

当前每日推荐只启用已验证稳定的网易云入口；QQ 音乐和酷狗的每日推荐接口可用性不稳定时不会作为稳定功能承诺。


## 开发环境

1. 安装 Flutter，并确保 `flutter` 在 PATH 中可用。
2. 拉取依赖：

```powershell
flutter pub get
```

3. 运行测试：

```powershell
flutter test --no-pub --reporter expanded -j 1
```

## 项目作用

Mconnect 的目标是把多个音乐平台分散的内容入口集中到一个 Android 应用里。用户不需要在网易云音乐、QQ 音乐和酷狗音乐之间反复切换，就可以在同一个搜索框里查找歌曲或歌单，并把播放、歌词、收藏、下载、本地音乐和听歌历史放进统一的使用流程。

这个项目重点解决的是“多平台音乐管理体验割裂”的问题。不同平台的搜索结果、播放链接、歌词格式、歌单结构和账号状态都不一致，Mconnect 在代码层通过平台适配层把这些差异包装起来，上层页面只处理统一的 `Song`、`Playlist`、`User` 和 `AudioQuality` 等模型。这样播放器、搜索页、音乐库和下载管理可以使用同一套业务逻辑，不需要为每个平台重复写一套界面。

## 使用场景

- 想同时搜索网易云、QQ 音乐和酷狗音乐中的歌曲，快速比较不同平台的资源可用性。
- 想用一个播放器管理跨平台播放队列，而不是在多个官方 App 之间切换。
- 想查看带时间轴的歌词，并让歌词跟随播放进度滚动。
- 想把跨平台歌曲加入“我喜欢”或自建歌单，形成应用内统一音乐库。
- 想导入别人分享的歌单链接，将外部歌单整理到自己的歌单列表中。
- 想扫描本地音乐文件夹，把本地歌曲和同名歌词文件纳入同一个播放器。
- 想下载可用歌曲，并通过下载管理查看进度、打开目录或删除本地文件。

## 核心工作流

1. 搜索歌曲或歌单：用户选择平台和搜索类型，应用调用对应平台适配器获取结果。
2. 播放音乐：搜索结果、歌单详情、本地音乐、每日推荐和听歌历史都可以进入统一播放器。
3. 同步歌词：播放器根据当前歌曲平台和歌曲 ID 获取歌词，解析时间轴后跟随播放进度高亮。
4. 管理音乐库：用户可以查看喜欢的歌曲、听歌历史、平台歌单、导入歌单和本地音乐。
5. 下载歌曲：下载管理器根据歌曲平台、音质和保存目录创建任务，并维护下载状态。
6. 记录状态：应用会保存播放进度、主题设置、歌单数据和下载目录等本地状态，让下次启动可以继续使用。

## 架构思路

项目采用 feature-first 结构，业务页面按功能拆分在 `lib/features/` 下，平台接口按音乐源拆分在 `lib/platform/` 下。核心思路是把“平台差异”限制在平台层，把“用户体验”放在统一的功能层。

- `platform/`：封装网易云、QQ 音乐和酷狗的搜索、播放、歌词、登录、歌单和下载接口。
- `features/player/`：负责播放队列、播放状态、全屏播放器、迷你播放器、歌词显示和音质选择。
- `features/library/`：负责我喜欢、听歌历史、平台歌单、导入歌单和歌单详情。
- `features/download/`：负责下载任务、下载目录、进度状态和文件操作。
- `features/local_music/`：负责扫描本地目录、识别音频文件和匹配本地歌词。
- `core/`：提供路由、数据库、网络、主题、诊断日志和通用组件。

这种拆分让项目后续扩展更直接：如果要接入新平台，优先新增一个平台适配器；如果要优化播放器体验，主要集中在 player feature 内；如果要调整下载策略，则集中在 download feature 内。
