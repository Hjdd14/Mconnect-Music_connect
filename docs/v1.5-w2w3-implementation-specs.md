# A. Last.fm + ListenBrainz scrobble（给 W2-D）

## A.0 设计总览（先定架构，再写代码）

```
          ┌─────────────────────────────┐
          │  ScrobbleEntry (本地一次听歌) │  ← 由 ListeningStatsTracker 触发
          └──────────────┬──────────────┘
                         ▼
          ┌─────────────────────────────┐
          │   ScrobbleQueue (drift)      │  离线优先：先落库，再后台补交
          └──────────────┬──────────────┘
                         ▼
          ┌─────────────────────────────┐
          │  ScrobbleBackend (接口)      │   nowPlaying / scrobble / validate
          └───────┬─────────────┬───────┘
                  │             │
      LastFmCompatible      ListenBrainzNative
      (api_sig + sk)         (Authorization: Token)
      ├ Last.fm              ├ ListenBrainz  api.listenbrainz.org
      ├ Libre.fm             └ Maloja          <实例地址>（LB 兼容端点）
      └ 自建 GNU FM
```

**为什么不做 LB 的 Last.fm 兼容代理（`proxy.listenbrainz.org`）作为主路径**：LB 的兼容实现要求请求带一个**在 LB 登记的 `api_key`**（服务端 `Token.is_valid_api_key(api_key)` 校验）并完成 `auth.getToken → /api/auth/ → auth.getSession` 交换；而 LB 原生 JSON API 只需要用户从设置页复制一个 **user token** 粘贴进来即可。对本仓库（无后端、用户自助配置）来说前者多一层门槛且没有任何收益。兼容代理的价值是「让 VLC / Spotify 这类**已有** Last.fm 客户端指过来」，不是给自研客户端用。
证据：[ListenBrainz api-compat](https://listenbrainz.readthedocs.io/en/latest/users/api-compat.html)、[ListenBrainz 服务端 api_compat.py](https://raw.githubusercontent.com/metabrainz/listenbrainz-server/master/listenbrainz/webserver/views/api_compat.py)（`record_listens` / `get_token` / `get_session` 里都能看到 `Token.is_valid_api_key(api_key)`）。

> 顺带一个重要事实：LB 的兼容层**只读 `api_sig` 但不校验它**（`for key, value in data.items(): if key in ["sk","token","api_key","method","api_sig","format"]: continue`）。所以给 Last.fm 写的签名代码在 LB 上不会因为签名细节被拒——但我们仍必须实现签名，因为 Last.fm 会校验（错误码 13）。

## A.1 Last.fm：端点、参数与 `api_sig` 算法

### A.1.1 传输层约定
- 单一入口：`https://ws.audioscrobbler.com/2.0/`（`method=` 选择操作）。
- **读方法** GET；**写方法必须 POST**，body 为 `application/x-www-form-urlencoded`（UTF-8）。
- 想要 JSON 就带 `format=json`（默认 XML）。`format` 与 `callback` **不参与签名**。
- 每个请求都要带 `api_key`；所有写/鉴权方法还要带 `api_sig`，写方法还要带 `sk`（session key）。

### A.1.2 `api_sig` 算法（**原文**）
> "MD5 signature of all request parameters (**excluding format and callback**) sorted alphabetically by name, concatenated as **name+value** pairs, with the **shared secret appended**."
> —— [api-evangelist/lastfm `authentication/lastfm-authentication.yml`](https://raw.githubusercontent.com/api-evangelist/lastfm/refs/heads/main/authentication/lastfm-authentication.yml)（派生自 `openapi/lastfm-openapi-original.yml`，同一句话也出现在 `lastfm-auth-api-openapi.yml` / `lastfm-track-api-openapi.yml` 的 `securitySchemes.SignedAuth`）

独立实现交叉验证（[kopuz-scrobble `src/scrobble/lastfm.rs`](https://docs.rs/kopuz-scrobble/0.16.0/src/scrobble/lastfm.rs.html)）：

```rust
fn make_api_sig(params: &[(&str, &str)], api_secret: &str) -> String {
    let mut sorted = params.to_vec();
    sorted.sort_by(|a, b| a.0.cmp(b.0));   // 按 key 升序
    let mut sig = String::new();
    for (key, value) in sorted { sig.push_str(key); sig.push_str(value); }  // 无分隔符
    sig.push_str(api_secret);                                              // 末尾接 secret
    format!("{:x}", md5::compute(sig))                                     // 小写十六进制
}
```
注意该实现里 `format=json` 只在**算完签名之后**才被加进 form（`let api_sig = make_api_sig(&params, …); let mut form = params.clone(); form.push(("api_sig", &api_sig)); … url = format!("{}?format=json", API_URL)`），与"排除 format"的规则一致。

### A.1.3 Dart 实现（可直接粘贴；`crypto` 已是本仓库依赖）

```dart
import 'dart:convert';
import 'package:crypto/crypto.dart';

/// Last.fm / Libre.fm 签名。规则见 A.1.2。
/// [params] 必须与实际发出去的参数**逐字一致**（含批量时的 artist[0]、timestamp[0] 等 key）。
/// 不要在这里放 format / callback / api_sig 本身。
String lastFmApiSig(Map<String, String> params, String sharedSecret) {
  final keys = params.keys
      .where((k) => k != 'format' && k != 'callback' && k != 'api_sig')
      .toList()
    ..sort();
  final buffer = StringBuffer();
  for (final k in keys) {
    buffer.write(k);
    buffer.write(params[k]);
  }
  buffer.write(sharedSecret);
  return md5.convert(utf8.encode(buffer.toString())).toString();
}
```

> ⚠️ 两个真实的踩坑点：
> 1. 参与签名的 value 必须是**字符串原样**。`trackNumber` 是 int 时，签名词必须和 form 里的 `"8"` 一致（别一边 `8` 一边 `"08"`）。
> 2. 批量请求的 key 含 `[` `]`，排序是**普通字典序**（`artist[0]` < `artist[10]` < `artist[2]`）。Last.fm 服务端按同一规则重算，所以照抄即可，**不要**自己改写 key 顺序。

### A.1.4 `track.scrobble`（写）

| 参数 | 必填 | 说明 |
|---|---|---|
| `method` | ✅ | `track.scrobble` |
| `api_key` | ✅ | 应用 API key |
| `artist` | ✅ | 批量时用数组记号 `artist[i]` |
| `track` | ✅ | 批量时 `track[i]` |
| `timestamp` | ✅ | 开始播放的 Unix 秒；批量时 `timestamp[i]` |
| `sk` | ✅ | session key |
| `api_sig` | ✅ | A.1.2 |
| `album` / `albumArtist` / `trackNumber` / `duration` / `mbid` / `streamId` / `chosenByUser` / `context` | ❌ | 可选，提升匹配率；批量时同样加 `[i]` |

- **单请求最多 50 条**（数组记号批量）："Up to 50 scrobbles may be sent in a single batch using array notation (`artist[0]`, `track[0]`, `timestamp[0]` etc.)"（[lastfm-track-api-openapi.yml](https://raw.githubusercontent.com/api-evangelist/lastfm/refs/heads/main/openapi/lastfm-track-api-openapi.yml)），并被结构化限流文档独立确认："Scrobble batches are hard-capped at 50 scrobbles per request"（[lastfm-rate-limits.yml](https://raw.githubusercontent.com/api-evangelist/lastfm/refs/heads/main/rate-limits/lastfm-rate-limits.yml)）。

### A.1.5 `track.updateNowPlaying`（写）
必填 `method` / `api_key` / `artist` / `track` / `sk` / `api_sig`；可选 `album`、`albumArtist`、`trackNumber`、`context`、`duration`、`mbid`。**没有 `timestamp`**（"now playing" 不是一个 listen）。响应只是 `{"status":"ok"}` 类包装。

**响应体（`track.scrobble`）**：`scrobbles.@attr.accepted` / `ignored`，逐条 `scrobble[].{track,artist,album,albumArtist}.corrected` 与 `ignoredMessage.code`。
⚠️ 重要语义：**`ignored` 可能 > 0 而 HTTP 仍是 200**。W2-D 必须读 `@attr.ignored`，并记录每条 `ignoredMessage.code`，否则用户会静默丢 scrobble。

## A.2 Last.fm 鉴权流程（三条路径）

### 路径 1：Web/token 流程（**推荐，全平台可用**）
1. `GET https://ws.audioscrobbler.com/2.0/?method=auth.getToken&api_key=<KEY>&format=json` → `{"token":"…"}`。
2. 用 `url_launcher` 打开 `https://www.last.fm/api/auth/?api_key=<KEY>&token=<TOKEN>`（见 [kopuz `auth_url`](https://docs.rs/kopuz-scrobble/0.16.0/src/scrobble/lastfm.rs.html)）。
3. 用户在浏览器里授权后回到 App（本仓库已有 `mconnect://` 深链与 `LinkSource` 接线，可直接复用；也可让用户手动点"我已授权"）。
4. `POST https://ws.audioscrobbler.com/2.0/`，form：`method=auth.getSession`、`api_key`、`token`、`api_sig`（签名覆盖 `api_key`+`method`+`token`）→ `{"session":{"name":…,"key":…}}`。

> `auth.getSession` 在官方规范里是 GET（[lastfm-auth-api-openapi.yml](https://raw.githubusercontent.com/api-evangelist/lastfm/refs/heads/main/openapi/lastfm-auth-api-openapi.yml) 标 `get`），而可直接运行的真实实现用 POST 也成功（kopuz 的 `get_session_key` 用 `client.post`）。**建议统一 POST**：写方法必须 POST，POST 对 getSession 同样被接受，且避免 token 出现在 URL/日志里。

### 路径 2：`auth.getMobileSession`（可选，桌面更省事）
`POST` form：`method=auth.getMobileSession`、`api_key`、`username`、`password`、`api_sig`（签名覆盖 username+password+api_key+method）→ `{"session":{…}}`。
- 必须 POST：Last.fm 明确不允许密码出现在 query string（社区记录的报错就是 "Must not send passwords in query string"，[SO 20664360](https://stackoverflow.com/questions/20664360)）。
- ⚠️ **待验证**：官方 `last.fm/api/mobileauth` 页面要求应用被开通移动端权限，原文本次未能取得（403）。**不要把 mobile session 作为唯一登录路径**；先发布 token 流程，mobile session 作为"实验性可选"（并在设置页标注）。

### 路径 3：Libre.fm（同协议，不同 base）
Libre.fm 官方 wiki 给出的映射关系（[Libre.fm fundamentals](https://raw.githubusercontent.com/wiki/libre-fm/developer/Libre.fm-fundamentals.md)）：

| Libre.fm | Last.fm 对应 |
|---|---|
| `libre.fm/2.0/` | `ws.audioscrobbler.com/2.0/` |
| `turtle.libre.fm` | `post.audioscrobbler.com`（旧 AudioScrobbler v1.2） |

即：**同一段签名代码 + 换 baseUrl 即可**。API key 需 32 字符（wiki：「These need to be 32 characters in length. Get an API key at https://libre.fm/api-keys.php」）；第三方库实测"当前不需要真的申请 key，可填任意值"，但你应**在设置页让用户填自己的 key**，不要依赖这个随时可能变的行为（[multi-scrobbler Libre.fm 文档](https://raw.githubusercontent.com/FoxxMD/multi-scrobbler/refs/heads/master/docsite/docs/configuration/clients/librefm.mdx)：「No API account, API Key, or Secret is currently needed… Instead, use any values」，并给出 `urlBase` = `protocol://libre.tld/path/prefix`，例：`https://my.cool.libre.com/2.0/`）。

## A.3 ListenBrainz 原生 API

- **API Root**：`https://api.listenbrainz.org`（**只支持 HTTPS**）。
- **鉴权头（逐字）**：`Authorization: Token <USER_TOKEN>`（[LB API index](https://listenbrainz.readthedocs.io/en/latest/users/api/index.html)）。
- **User-Agent 必须带**，否则可能被静默封禁：格式 `Application name/<version> ( contact-url )` 或 `( contact-email )`，例 `Mconnect/1.5.0 ( https://github.com/… )`（同上页面）。**这条是硬要求**，W2-D 必须在 dio 全局或该后端的请求头里加。

### A.3.1 `POST /1/submit-listens`

请求体（[LB JSON 文档](https://listenbrainz.readthedocs.io/en/latest/users/json.html)）：

```json
{
  "listen_type": "single",              // single | import | playing_now
  "payload": [
    {
      "listened_at": 1443521965,        // playing_now 时**必须省略**
      "track_metadata": {
        "artist_name": "Rick Astley",   // 必填
        "track_name": "Never Gonna Give You Up", // 必填
        "release_name": "Whenever you need somebody",
        "additional_info": {
          "media_player": "Mconnect",
          "media_player_version": "1.5.0",
          "submission_client": "Mconnect",
          "submission_client_version": "1.5.0",
          "duration_ms": 222000,
          "music_service": "music.163.com",
          "origin_url": "https://music.163.com/#/song?id=…"
        }
      }
    }
  ]
}
```

- `single`：payload **恰好 1 条**；`import`：≥1 条（离线补交用这个）；`playing_now`：恰好 1 条、**不得有 `listened_at`**、payload 只是临时状态（"Playing Now listens are only stored temporarily. A playing now listen must be submitted again as a `single` or `import` for permanent storage."）。
- `listened_at` 应填**播放开始时间**（"This should be set to playback start time of the submitted track"），最小允许值 `LISTEN_MINIMUM_TS = 1033430400`（≈2002-10-01）。

### A.3.2 **单请求上限（精确值）**

| 常量 | 值 | 含义 |
|---|---|---|
| `MAX_LISTENS_PER_REQUEST` | **1000** | 单请求最多条数 |
| `MAX_LISTEN_PAYLOAD_SIZE` | **10240000** B（≈10 MB） | 整个请求体上限 |
| `MAX_LISTEN_SIZE` | **10240** B（10 KB） | 单条 listen 上限 |
| `MAX_DURATION_LIMIT` / `MAX_DURATION_MS_LIMIT` | 2073600 s / 2073600000 ms | duration 上限（24 天） |
| `MAX_TAGS_PER_LISTEN` / `MAX_TAG_SIZE` | 50 / 64 | tags |
| `MAX_ITEMS_PER_GET` / `DEFAULT_ITEMS_PER_GET` | 1000 / 25 | 读取 |

来源：[LB Core API（Constants 段）](https://listenbrainz.readthedocs.io/en/latest/users/api/core.html)。**实践建议批量 50 条/请求**（与 Last.fm 对齐，一条回归路径覆盖两个后端，且远低于 1000 上限）。

### A.3.3 `/1/validate-token`
`GET /1/validate-token`，带 `Authorization: Token <t>`。成功：`{"code":200,"message":"Token valid.","valid":true,"user_name":"<MBID>"}`；无效：`{"valid":false}`。也接受 `?token=` 参数（仅为向后兼容，**不要用**，会进日志）。
用途：设置页"测试连接"按钮，成本 1 次请求、无副作用。

### A.3.4 其它可顺手用上的端点

## A.5 计次规则（权威出处）与 `playing_now` 的关系

**权威表述（ListenBrainz 官方文档，逐字）**：
> "Listens should be submitted for tracks when the user has listened to **half the track or 4 minutes of the track, whichever is lower**. If the user hasn't listened to 4 minutes or half the track, it doesn't fully count as a listen and should not be submitted."
> —— [LB Core API](https://listenbrainz.readthedocs.io/en/latest/users/api/core.html)

Last.fm 侧同一规则的表述（同源规范）："A track must be **longer than 30 seconds** and listened to for at least half its duration or 4 minutes (whichever comes first)."（[lastfm-track-api-openapi.yml](https://raw.githubusercontent.com/api-evangelist/lastfm/refs/heads/main/openapi/lastfm-track-api-openapi.yml)）

**落地阈值（照此实现）**：

```dart
/// 是否够计一次 listen。threshold = min(duration/2, 4min)。
bool shouldScrobble({required Duration actualPlayed, required Duration trackDuration}) {
  if (trackDuration <= const Duration(seconds: 30)) return false;       // 太短不计
  final half = Duration(milliseconds: trackDuration.inMilliseconds ~/ 2);
  final threshold = half < const Duration(minutes: 4) ? half : const Duration(minutes: 4);
  return actualPlayed >= threshold;
}
```

**`playing_now` 与 scrobble 的关系**（LB 文档原文）：playing now 只是临时状态，必须再以 `single`/`import` 提交一次才能永久保存；两者**互不替代**。因此在 Mconnect：

- **切歌时**（`sameSong == false` 且 `isPlaying`）→ 发 `nowPlaying`（Last.fm: `track.updateNowPlaying`；LB: `playing_now`）；
- **累计播放时长达阈值时（或离场/切歌/退到后台时结算）** → 入队 `scrobble`；
- `nowPlaying` 失败**不重试、不落库**（它是瞬时状态，补交无意义，只会污染队列）。

**重复提交的处理**：
- Last.fm：同一 `(artist, track, timestamp)` 重复提交**会产生重复记录**——官方没有幂等键。因此必须**本地去重**：队列表对 `(serviceId, songId, playedAt 秒)` 建唯一索引，`state=sent` 后不再重发。
- LB：`import` 模式用于补交历史；官方未承诺去重，采取同样的本地唯一约束即可。
- 暂停/继续不算新的一次 listen（本仓库 `ListeningStatsTracker` 已经有 `restartThreshold = 5s` 的"是否从头开始"判定，直接复用其 `PlayEventSource.play/resume` 语义）。

## A.6 失败语义、退避与离线补交

### A.6.1 语义表

| 服务 | 信号 | 含义 | 处理 |
|---|---|---|---|
| Last.fm | HTTP 200 + `<error code="13">` | **invalid method signature**（签名算错） | 致命：打日志（签名内容经 redactor）并**停止重试**，提示用户"暂不支持，请反馈" |
| Last.fm | code `9` | invalid session key（用户撤销/过期） | 致命：清 `sk`，设置页提示重新登录 |
| Last.fm | code `10` | invalid api key | 致命（应用配置问题） |
| Last.fm | code `16` | service temporarily unavailable | 可重试（指数退避） |
| Last.fm | code `29` | rate limit exceeded | 可重试（指数退避，≥30s 起） |
| Last.fm | code `26` | **suspended api key** | 致命且需人工处理（应用被限流封禁） |
| Last.fm | code `6` / `8` | invalid parameters / operation failed | 单条丢弃（不要卡住整队列） |
| Last.fm | HTTP 429 / 403 / 503 | throttled / quotaExceeded / serviceUnavailable | 可重试；读 `Retry-After` |
| LB | HTTP 400 | invalid JSON | 致命（我们自己的 bug） |
| LB | HTTP 401 | token 无效 | 致命：清 token，提示重新粘贴 |
| LB | HTTP 429 | 限流 | 可重试；用 `X-RateLimit-Reset-In` 决定等待秒数 |
| 任意 | 网络异常/超时 | 未知 | 可重试 |

**限流的事实基线**：
- Last.fm：约 **5 req/s per originating IP**，且"连续每秒多次调用可能被暂停账号"；限流以**数字错误码**而非 RFC 头表达（无标准 RateLimit 头）。来源：[lastfm-rate-limits.yml](https://raw.githubusercontent.com/api-evangelist/lastfm/refs/heads/main/rate-limits/lastfm-rate-limits.yml)（其中也标了 `errorCodes: 13/16/26/29` 与 `scrobbles_per_request: 50`；该文件是第三方结构化整理，官方对应页 `last.fm/api/intro`）。
- ListenBrainz：**"每个客户端每秒不得超过 1 次调用"**，并提供 `X-RateLimit-Limit` / `X-RateLimit-Remaining` / `X-RateLimit-Reset-In`（推荐用它，抗客户端时钟错误）/ `X-RateLimit-Reset`；超限返回 **429**。来源：[LB API index → Rate limiting](https://listenbrainz.readthedocs.io/en/latest/users/api/index.html)。

**退避建议（照此实现）**：全局串行一个"scrobble 泵"（单 worker），两次请求之间**至少 1.2 s**（同时满足 LB 的 1 req/s 与 Last.fm 的 5 req/s 上限）；可重试失败按 `min(2^attempt, 15min)` 退避并加 ±20% 抖动；429/`29` 直接采用服务端提示或 ≥30 s。

### A.6.2 离线补交的正确姿势

1. **离线优先**：`scrobble` 事件先写 drift 队列（`state=pending`），立刻 `return`。UI 永不等待网络。
2. **补交时填原始时间**：用 `timestamp[i]`（Last.fm）/ `listened_at`（LB）**保留最初播放时间**，不要用"现在"。`import` 类型正是为这种批量历史补交准备的。
3. **批量与顺序**：按 `playedAt` 升序、每批 ≤50 条；一次只在飞一批，成功后再发下一批（避免限流）。
4. **`playing_now` 不补交**（A.5）。
5. **时间上限**：⚠️ 本调研**未能取得** Last.fm 关于"过旧 timestamp 被拒"的官方原文（last.fm 全站 403，且相关 SO 页亦 403），因此**不要写死 14 天**。保守实现：
   - 本地只保留最近 **30 天**的 pending 队列（更早的直接标记 `dropped` 并在诊断页可见）；
   - 校验下界用 LB 的可引用常量 `LISTEN_MINIMUM_TS = 1033430400`（[LB Core](https://listenbrainz.readthedocs.io/en/latest/users/api/core.html)）；
   - 首次实测：故意提交一条 40 天前的时间戳，把错误码记进本文件（见 E 节待验证清单）。
6. **凭据失效要停泵**：任一后端返回致命码（`9/10/13/26`、401）时，把该后端标为 `needsReauth` 并停止向它发请求——否则每次播放都白撞一次网络。
7. **可观测**：设置页显示每个后端「待补交 N 条 / 上次成功时间 / 上次错误」。

## A.7 隐私：token 不能进日志（**本仓库已有 redactor，但有缺口**）

- 凭据一律进 `flutter_secure_storage`（已是依赖），key 形如 `scrobble.lastfm.sk` / `scrobble.listenbrainz.token`。
- 日志一律经 `DiagnosticsRedactor.redactText(...)`（`lib/core/diagnostics/diagnostics_redactor.dart`）。

**⚠️ 实测缺口（必须修）**：现有 `sensitiveKeys` 里**没有 `sk`**，也**不匹配 `api_sig`**——规则 3 的正则要求敏感词出现在 key 的**结尾**，而 `api_sig` 以 `sig` 结尾、`sk` 干脆不在表里。也就是说：

```
POST https://ws.audioscrobbler.com/2.0/  body: api_key=…&sk=SECRET&api_sig=…&artist=…
```
其中 `api_sig=…` 与 `sk=…` **都不会被脱敏**（该行不是 URL query，规则 5 的整段 query 脱敏也不生效）。

修法（两行，且与本文件已声明的"宁可多脱敏"哲学一致）：

```dart
static const Set<String> sensitiveKeys = {
  // …原有…
  'sk',        // Last.fm / Libre.fm session key
  'api_sig',   // Last.fm 签名（等价于凭据）
};
```
副作用要先知道：规则要求"key 以敏感词结尾"，所以加 `sk` 后 `task=`、`disk=`、`risk=` 这类普通键也会被脱敏。按该文件自己的注释（"a missed parameter is a leaked credential while a lost parameter is just a less convenient log line"）这是**可接受的**；若不接受，就在 scrobble 后端里**自己**把 `api_key/sk/api_sig/token` 替换成 `<redacted>` 后再 `DiagnosticsService.record`，并补一条单测。
另外：LB 的 token 出现在 `Authorization: Token …` 头里——规则 1（`authorization\s*:\s*…`）会整行脱敏，但若你在代码里把 token 拼进自定义日志（如 `'token=$t'`），只有加了 `token` 的规则 3 能兜住。

### 3) `android/app/src/main/kotlin/com/mconnect/mconnect/MconnectWidgetProvider.kt`
以官方示例为模板改写（[HomeWidgetExampleProvider.kt](https://raw.githubusercontent.com/ABausG/home_widget/main/packages/home_widget/example/android/app/src/main/kotlin/es/antonborri/home_widget_example/HomeWidgetExampleProvider.kt)）：

```kotlin
package com.mconnect.mconnect

import android.appwidget.AppWidgetManager
import android.content.Context
import android.content.SharedPreferences
import android.graphics.BitmapFactory
import android.net.Uri
import android.view.View
import android.widget.RemoteViews
import es.antonborri.home_widget.HomeWidgetBackgroundIntent
import es.antonborri.home_widget.HomeWidgetLaunchIntent
import es.antonborri.home_widget.HomeWidgetProvider

/**
 * 小组件渲染。数据由 Dart 侧 HomeWidget.saveWidgetData 写入，
 * 框架把同一份 SharedPreferences 作为 widgetData 传进来 —— 进程被杀/应用未启动时也能读。
 */
class MconnectWidgetProvider : HomeWidgetProvider() {
    override fun onUpdate(
        context: Context,
        appWidgetManager: AppWidgetManager,
        appWidgetIds: IntArray,
        widgetData: SharedPreferences,
    ) {
        appWidgetIds.forEach { widgetId ->
            val views = RemoteViews(context.packageName, R.layout.mconnect_widget).apply {
                // 1) 整块点击 → 打开 App（可带路由 URI）
                setOnClickPendingIntent(
                    R.id.widget_container,
                    HomeWidgetLaunchIntent.getActivity(
                        context,
                        MainActivity::class.java,
                        Uri.parse("mconnect://widget/open"),
                    ),
                )

                // 2) 文本：无播放时显示占位，不要留空
                setTextViewText(
                    R.id.widget_title,
                    widgetData.getString("title", null) ?: "Mconnect",
                )
                setTextViewText(
                    R.id.widget_artist,
                    widgetData.getString("artist", null) ?: "未在播放",
                )

                // 3) 封面（Dart 侧用 saveFile/saveImage 落盘，这里拿到的是绝对路径）
                val cover = widgetData.getString("coverPath", null)
                if (cover != null) {
                    setImageViewBitmap(R.id.widget_cover, BitmapFactory.decodeFile(cover))
                    setViewVisibility(R.id.widget_cover, View.VISIBLE)
                } else {
                    setViewVisibility(R.id.widget_cover, View.GONE)
                }

                // 4) 播放/暂停：交给 Dart 在后台执行
                setImageViewResource(
                    R.id.widget_play_pause,
                    if (widgetData.getBoolean("isPlaying", false))
                        android.R.drawable.ic_media_pause
                    else android.R.drawable.ic_media_play,
                )
                setOnClickPendingIntent(
                    R.id.widget_play_pause,
                    HomeWidgetBackgroundIntent.getBroadcast(
                        context,
                        Uri.parse("mconnect://widget/togglePlayPause"),
                    ),
                )
            }
            appWidgetManager.updateAppWidget(widgetId, views)
        }
    }
}
```

## B.3 进程被杀 / 应用未运行时的状态从哪来

- **机制**：Dart 用 `HomeWidget.saveWidgetData<T>('key', value)` 写入共享存储；原生 `HomeWidgetProvider.onUpdate(..., widgetData: SharedPreferences)` **直接拿到同一份数据**；`HomeWidget.updateWidget(name: 'MconnectWidgetProvider')` 触发重绘。文档原文："By default home_widget uses UserDefaults on iOS and **SharedPreferences on Android** to store data."、"Primitive values (strings, numbers, booleans, etc.) are stored directly… For **binary payloads** (images, or any bytes), write a file with `saveFile`/`saveImage` and use the same **`id`** with `getWidgetData`: the value will be the **absolute path** to the file on disk, which your widget can open natively."
  来源：[sync-data](https://raw.githubusercontent.com/ABausG/home_widget/main/docs/usage/sync-data.mdx)、[update-widget](https://raw.githubusercontent.com/ABausG/home_widget/main/docs/usage/update-widget.mdx)。
- **结论**：**进程被杀 = 状态不丢**，因为数据在 SharedPreferences，原生渲染不依赖 Flutter 进程；**没有播放时**由 B.2 的 `?: "Mconnect"` / `?: "未在播放"` 兜底（永远不要留空字符串或崩溃）。
- ⚠️ **待验证**：SharedPreferences **文件名**本调研未取得源码确认。**不要**在别的原生组件里硬编码文件名去读；用文档给出的两条正路：原生侧继承 `HomeWidgetProvider`（拿 `widgetData` 参数），或在其它原生代码里用插件提供的 `HomeWidgetPlugin.getData(context)`（本调研未能取到该 Kotlin 文件正文——`jsdelivr` 返回 `application/octet-stream`、`raw.githubusercontent` DNS 抖动）。落实现场用 IDE 跳转确认一次即可。

**调用时机（照此实现）**：
| 时机 | 动作 |
|---|---|
| 播放开始 / 切歌 | `saveWidgetData('title'|'artist', …)` 等字段 → `updateWidget(name: 'MconnectWidgetProvider')` |
| 播放 / 暂停状态变化 | `saveWidgetData<bool>('isPlaying', …)` → `updateWidget(...)` |
| App 进后台（`AppLifecycleState.paused`，钩子已在 `lib/app.dart:227`） | 再同步一次（保证最后一次状态落盘） |
| 封面变化 | `saveImage`/`saveFile` 落盘 → `saveWidgetData('coverPath', 绝对路径)`（**别把 bytes 存进 prefs**） |
| 首次安装/加组件到桌面 | 用当前队列状态立刻同步一次（`onUpdate` 会被系统触发） |

## B.4 点击跳转：从小组件唤起 App 到具体路由

1. 原生侧用 `HomeWidgetLaunchIntent.getActivity(context, MainActivity::class.java, Uri.parse("mconnect://widget/open"))` 构造 PendingIntent（B.2 已写），或 `HomeWidgetBackgroundIntent.getBroadcast(...)` 走后台 Dart 回调。
2. Dart 侧两种入口：
   - App **冷启动**：`await HomeWidget.initiallyLaunchedFromHomeWidget()` → `Future<Uri?>`；
   - App **已在运行**：订阅 `HomeWidget.widgetClicked`（`Stream<Uri?>`）。
   来源：[detect-clicks](https://raw.githubusercontent.com/ABausG/home_widget/main/docs/features/detect-clicks.mdx)。
3. **不要**把这条路直接接到 `app_links`：两者是**不同 action**（widget 走 `es.antonborri.home_widget.action.LAUNCH`，app_links 只听 `ACTION_VIEW`），因此不会重复投递，但也**不会**被 `AppLinksSource` 收到。正确做法是**实现一个新的 `LinkSource` 并组合**——本仓库 `deep_link_service.dart` 的 `LinkSource` 抽象正是为此留的缝：

```dart
// lib/core/share/home_widget_link_source.dart（新增）
import 'dart:async';
import 'package:flutter/foundation.dart';
import 'package:home_widget/home_widget.dart';
import 'deep_link_service.dart';

/// 把「小组件点击」并入现有深链管线。
/// Windows 上没有 home_widget 实现，必须靠 [supported] 守护，否则 MissingPluginException。
class HomeWidgetLinkSource implements LinkSource {
  const HomeWidgetLinkSource();

  static bool get supported => !kIsWeb && defaultTargetPlatform == TargetPlatform.android;

  @override
  Future<Uri?> initialLink() async =>
      supported ? await HomeWidget.initiallyLaunchedFromHomeWidget() : null;

  @override
  Stream<Uri> links() => supported
      ? HomeWidget.widgetClicked.where((uri) => uri != null).cast<Uri>()
      : const Stream<Uri>.empty();
}

/// 组合：app_links（mconnect:// 分享/深链）+ 小组件。
class CompositeLinkSource implements LinkSource {
  const CompositeLinkSource(this._sources);
  final List<LinkSource> _sources;

  @override
  Future<Uri?> initialLink() async {
    for (final s in _sources) {
      final uri = await s.initialLink();
      if (uri != null) return uri;
    }
    return null;
  }

  @override
  Stream<Uri> links() => _sources.map((s) => s.links()).fold(
        const Stream<Uri>.empty(),
        (a, b) => a.isEmpty ? b : Stream<Uri>.multi((c) {
          final s1 = a.listen(c.add);
          final s2 = b.listen(c.add);
          c.onCancel = () async { await s1.cancel(); await s2.cancel(); };
        }),
      );
}
```
接线只需改 `deep_link_wiring.dart:37` 的默认值调用点（例如在 `app.dart` 里调用时传 `source: const CompositeLinkSource([AppLinksSource(), HomeWidgetLinkSource()])`）。`DeepLinkService._handle` 的去重逻辑（`_initialLink`）对单次冷启动链接已足够；**唯一注意点**：widget 的 `mconnect://widget/...` URI 会进入 `ShareLinks.classify`，若它不被识别会返回 `null`（不会乱跳，符合现有"未识别链接不得移动用户"的约定）——如需跳转到播放页，请在 `ShareLinks` 里**显式**加一条 `widget` 路由映射（这是一个独立的小改动，别偷懒让它在分类里落空）。

## B.5 RemoteViews vs Glance：**本仓库推荐 RemoteViews**（XML）

| 维度 | RemoteViews（XML） | Jetpack Glance（Compose） |
|---|---|---|
| 本仓库适配度 | ✅ 与"纯 Dart UI + 少量 Kotlin"一致：Kotlin 只写一个 ~40 行的 Provider | ❌ 需要在 `build.gradle.kts` 开 `buildFeatures { compose true }` 并引入 `androidx.glance:glance-appwidget`，等于在 Flutter 工程里**再开一套 Compose 工具链**（还有 Compose 编译器版本与 Kotlin 2.2.20 的匹配风险） |
| 代码量 | 1 个 XML 布局 + 1 个 Kotlin 类 | Kotlin Composable（更现代，但引入更多依赖） |
| 主题/深浅色 | 手写主题属性（要自己处理） | Compose 主题（更省事） |
| 官方立场 | 仍支持（`docs/android-xml/overview.mdx`："home_widget supports Android Widgets created with XML… going forward it is recommended to use the Jetpack Glance way"） | 推荐方向 |
| 官方示例支持度 | `HomeWidgetProvider`（RemoteViews 版）示例完整可抄 | 需 `HomeWidgetGlanceStateDefinition` + `HomeWidgetGlanceWidgetReceiver` |

**结论**：W3-A 第一版做「当前曲 + 播放/暂停」用 **RemoteViews**（成本最低、对 Gradle 零侵入、可抄的示例最多）。等外部依赖稳定、且有第二个小组件需求时再评估迁移 Glance。若确实要 Glance，必须做的两件事（否则组件不刷新）：`override val stateDefinition: GlanceStateDefinition<*>? get() = HomeWidgetGlanceStateDefinition()`；Receiver 继承 `HomeWidgetGlanceWidgetReceiver<AppWidget>`。来源：[Android Setup](https://raw.githubusercontent.com/ABausG/home_widget/main/docs/setup/android.mdx)。

## B.6 权限 / manifest / Windows / 已知坑

- **新增权限：0**。（只有用 `HomeWidget.scheduleWidgetUpdates` 定时刷新时才需要 `RECEIVE_BOOT_COMPLETED` 并注册 `HomeWidgetScheduledUpdateReceiver`；第一版不做定时刷新，`updatePeriodMillis` 已足够。）
- **manifest 改动：3 处**：receiver（APPWIDGET_UPDATE + meta-data）、MainActivity 的 LAUNCH intent-filter、（可选）HomeWidgetBackgroundReceiver。
- **Windows**：不会编译失败（B.1），但必须用 `HomeWidgetLinkSource.supported` 之类的守护；Dart 侧任何未守护的 `HomeWidget.*` 调用会在 Windows 运行时抛异常。
- **已知坑清单**：
  1. `android:exported` 必须显式 `true`（API 31+ 的 receiver 强制要求），漏了是**安装期**失败。
  2. `updatePeriodMillis` < 30 分钟无效。
  3. `res/xml` 里的 `android:description` 若引用不存在的 string 资源 → **编译失败**。
  4. 二进制只能走 `saveFile`/`saveImage` 落盘 + 传路径；不要把图片 bytes 塞 SharedPreferences（会 OOM/ANR）。
  5. 背景图/封面在外置存储时需要正确路径权限；用 `saveImage` 写进 App 私有目录更安全。
  6. `HomeWidget.widgetClicked` 要拿到 `onNewIntent`，依赖 `singleTop`（已有）。
  7. Release 构建开了 `isMinifyEnabled = true` + `isShrinkResources = true`（`android/app/build.gradle.kts:33-38`）：新增的 receiver/Provider 由 manifest 引用，R8 会保留；但如果之后用**自定义 drawable** 当小组件图标，需要 `res/raw/keep.xml` 的 `tools:keep`，否则会被 shrink 掉。
  8. 首次添加组件到桌面时 `onUpdate` 会立刻被调用，此时 Dart 可能还没启动 → **务必给所有 `widgetData.getString(...)` 兜底默认值**（B.2 已示范）。
  9. 小组件的 Dart→原生同步是**尽力而为**：不要在小组件上展示"精确进度条"这类需要秒级刷新的内容。

## C.2 browse tree 的**最低要求**（这是 EP-1/EP-2 的真正原因）

- `audio_service` 默认的 `BaseAudioHandler.getChildren` 返回**空列表**：
  > `Future<List<MediaItem>> getChildren(String parentMediaId, [Map<String, dynamic>? options]) async => [];`
  > —— [BaseAudioHandler.getChildren](https://pub.dev/documentation/audio_service/latest/audio_service/BaseAudioHandler/getChildren.html)
  即"只有控制、没有内容" → 正是 Play 审核判定的 **EP-1「Media content is not properly exposed to Android Auto」/ EP-2「App does not provide a compliant user interface for media browsing」**。
- 需要的三件套：
  1. 覆写 `getChildren`（对应原生 `onLoadChildren`）；
  2. 根 id 用 `AudioService.browsableRootId`（**静态常量**："The root media ID for browsing media provided by the background task"，[AudioService 常量表](https://pub.dev/documentation/audio_service/latest/audio_service/AudioService-class.html)）；
  3. 可选但推荐：`AudioServiceConfig(androidBrowsableRootExtras: {...})`（"Extras to report on Android in response to an `onGetRoot` request"，[AudioServiceConfig](https://pub.dev/documentation/audio_service/latest/audio_service/AudioServiceConfig-class.html)）；动态变化时用 `AudioHandler.subscribeToChildren` 推送。
- `audio_service` 作者（issue #1119 维护者回复）明确了对应关系："These correspond to the native Android APIs `onLoadChildren` and `onGetRoot`."（[issue #1119 评论](https://github.com/ryanheise/audio_service/issues/1119)）

**可直接粘贴的最小实现**（放进本仓库已有的 audio handler——`lib/features/player/data/playback_notification_service.dart` 附近的 handler 类）：

```dart
// 目录树（车机只认"根 → 分组 → 曲目"）：
static const _rootId = AudioService.browsableRootId; // audio_service 提供的静态常量
static const _idQueue = 'queue';
static const _idPlaylists = 'playlists';

@override
Future<List<MediaItem>> getChildren(String parentMediaId, [Map<String, dynamic>? options]) async {
  if (parentMediaId == _rootId) {
    return const [
      MediaItem(id: _idQueue, title: '当前播放', playable: false),
      MediaItem(id: _idPlaylists, title: '我的歌单', playable: false),
    ];
  }
  if (parentMediaId == _idQueue) {
    return queue.value; // 已有队列，直接暴露
  }
  if (parentMediaId == _idPlaylists) {
    return _playlistChildren(); // 名称 + playable:false，点进去再列曲目
  }
  if (parentMediaId.startsWith('playlist:')) {
    return _songsOf(parentMediaId.substring('playlist:'.length));
  }
  return const [];
}

/// 内容变化时通知车机重新拉取（否则车机列表会一直停在旧数据）
@override
Future<void> subscribeToChildren(String parentMediaId) async {
  queue.listen((_) => super.subscribeToChildren(parentMediaId));
}
```
配套要求：
- 每个可播放项都要有 `MediaItem.id`（车机用它回传 `playFromMediaId`）→ 在 `playFromMediaId` 里解析并播放；
- **必须有 `playable: true` 的叶子节点**，只有分组没有曲目同样会被判不合格；
- 曲目缺少真实内容（车机点进去是空的）也会被拒 —— 内容要来自本仓库已有的在线曲库/本地库/歌单，不要给占位。

## C.3 Play 审核的常见拒绝点（照此自查）

来自真实被拒案例（[audio_service issue #1119](https://github.com/ryanheise/audio_service/issues/1119)，2025-05 提出、2026 年仍在被追问，`state: open`）：
- **EP-1**：Media content is not properly exposed to Android Auto → 对应 C.2 的 browse tree 缺失；
- **EP-2**：App does not provide a compliant user interface for media browsing → 同上（没有可浏览层级）。

**自查清单（把这条清单当验收标准）**：
1. `getChildren(browsableRootId)` 返回**非空**且至少一条 `playable: true` 的**曲目**（不是只有分组）。
2. 车机能从根一路点到并**成功播放**一首歌（用 Desktop Head Unit 或真车验证）。
3. 播放后回到车机 UI 仍能看到"正在播放"的元数据（标题/歌手/封面）——`audio_service` 的通知/媒体会话本来就有，别在 Android Auto 场景下禁用。
4. 内容在本地库为空时也要有可播放内容（例如"当前队列"），否则首次启动就是空树 → 高风险被拒。
5. 遵守 Google 的[汽车应用质量要求](https://developer.android.google.cn/docs/quality-guidelines/car-app-quality?category=media&hl=en)（媒体类：分心控制、层级清晰、无广告/无付费墙阻断播放）。
6. 车机端**不要**做需要输入的操作；搜索建议用系统提供的语音/键盘入口。
7. 作者在 #1119 的立场值得记录：`audio_service` **只保证把底层 API 暴露出来**，AA 合规是**应用自己的责任**（"it's a matter of reading Android's own developer documentation about Android Auto, following their guides and steps"）。所以**不要**指望加个包就过审。

## C.4 权限 / 构建 / 坑
- **新增权限：0**（`automotive_app_desc.xml` 与 meta-data 都不是权限）。
- **Windows**：无影响（纯 Android 资源）。
- **坑**：
  1. 不装 Android Auto 的**真机/模拟器**：用 Google 的 **Desktop Head Unit (DHU)** 做本地验证；不验证就提交审核 = 高风险。
  2. `MediaBrowserService` 的 `android:exported="true"` 必须保留（本仓库已有）。
  3. 车机与手机是**两个进程/两个界面**：Dart 侧不能假设"当前页面"存在（`playFromMediaId` 可能在 App 未前台时被调用）——队列/播放逻辑必须能在 headless 状态下工作（本仓库已有 audio_service 后台 handler，注意别把依赖 `WidgetRef` 的逻辑塞进去）。
  4. 内容分级：不要暴露未授权内容（与 A/法务口径一致，见 W2 讨论）。

# D. 三个小依赖的接入要点

## D.1 `dynamic_color`（给 W3-B）

**能力事实**（[README](https://raw.githubusercontent.com/material-foundation/flutter-packages/main/packages/dynamic_color/README.md)、[DynamicColorBuilder](https://pub.dev/documentation/dynamic_color/1.9.0/dynamic_color/DynamicColorBuilder-class.html)）：
- Android **S+**：壁纸取色；**Windows / macOS / Linux**：取**系统强调色**（"macOS, Windows and Linux: the ColorSchemes are constructed from the accent Color provided by the system"）→ **Windows 不是"不支持"，是另一套来源**。
- 取不到时 builder 的 `lightDynamic`/`darkDynamic` 为 **`null`** → 必须回退。
- 已知历史坑：2024 年 issue [#582](https://github.com/material-foundation/flutter-packages/issues/582)「Package `dynamic_color` does not initialize new `ColorScheme` roles」——`primaryFixed`/`surfaceContainer*` 等会退化成 `primary`/`surface`；**该 issue 已于 2026-08-07 以 completed 关闭**。→ 结论：**用较新的 `dynamic_color`（1.9.x 及以上）**，不要长期钉在旧版本；升级后确认这几个 role 是否是动态色（受影响的正是 `navigationBarTheme`/`cardTheme` 这类会读 `surfaceContainer` 的地方）。
- 测试工具：`dynamic_color_testing`（dev 依赖）提供 `DynamicColorTestingUtils.setMockDynamicColors(...)`，可在 widget 测试里伪造动态色。

**接入现有 `theme_provider` / `app_theme`（最小侵入方案）**：
现状（`lib/app.dart:240,260-273`）：
```dart
final themeSettings = ref.watch(themeSettingsProvider);
final ThemeData lightTheme = switch (uiStyle) {
  UiStyle.material => AppTheme.light(seedColor: themeSettings.seedColor),
  UiStyle.miuix    => miuixTheme(brightness: Brightness.light, seedColor: themeSettings.seedColor),
};
```
建议**不改 `AppTheme` 的 API**，而是给 `ThemeSettings` 增加一个开关 + 可选动态色，并在 `app.dart` 外面包一层 `DynamicColorBuilder`：

```dart
// 1) theme_provider.dart：加字段与持久化（沿用同一 Hive box 'settings'）
class ThemeSettings {
  final ThemeMode mode;
  final Color seedColor;
  final bool useDynamicColor;   // 新增，默认 false（保持现有行为，升级不惊吓用户）
  const ThemeSettings({this.mode = ThemeMode.system, this.seedColor = AppTheme.defaultSeedColor, this.useDynamicColor = false});
  ThemeSettings copyWith({ThemeMode? mode, Color? seedColor, bool? useDynamicColor}) => ThemeSettings(
        mode: mode ?? this.mode,
        seedColor: seedColor ?? this.seedColor,
        useDynamicColor: useDynamicColor ?? this.useDynamicColor,
      );
}
// _load(): box.get('use_dynamic_color', defaultValue: false) as bool
// setUseDynamicColor(bool v): box.put('use_dynamic_color', v)

// 2) app.dart：包一层，null 即回退（API<31 / 桌面取不到强调色）
return DynamicColorBuilder(
  builder: (ColorScheme? lightDynamic, ColorScheme? darkDynamic) {
    final useDynamic = themeSettings.useDynamicColor;
    final ColorScheme? lightScheme = useDynamic ? lightDynamic : null;
    final ColorScheme? darkScheme  = useDynamic ? darkDynamic  : null;

    final ThemeData lightTheme = switch (uiStyle) {
      UiStyle.material => AppTheme.light(seedColor: themeSettings.seedColor, colorSchemeOverride: lightScheme),
      UiStyle.miuix    => miuixTheme(brightness: Brightness.light, seedColor: themeSettings.seedColor, colorSchemeOverride: lightScheme),
    };
    // …darkTheme 同理…
    return MaterialApp.router(/* 其余保持不变 */);
  },
);
```
`AppTheme.light/dark` 只需各加一个可选参数（**默认 null → 行为与现在完全一致**，零回归风险）：
```dart
static ThemeData light({Color seedColor = defaultSeedColor, ColorScheme? colorSchemeOverride}) {
  final colorScheme = colorSchemeOverride ?? ColorScheme.fromSeed(seedColor: seedColor, brightness: Brightness.light);
  return ThemeData(colorScheme: colorScheme, useMaterial3: true, /* …原样… */);
}
```
同理给 `lib/core/theme/miuix_theme.dart:54-66` 的 `base` 注入点加 `colorSchemeOverride`。

**回退（API<31）**：`DynamicColorBuilder` 在取不到时给 `null`，上面的 `?? ColorScheme.fromSeed(seedColor)` 就是回退路径——**不要再写 `Platform.isAndroid && sdkInt>=31` 的分支判断**，因为 Windows 也走同一条 builder（有强调色就用，没有就 null）。
**设置页**：加一个 "使用系统动态取色" 开关；在 `lightDynamic == null && darkDynamic == null` 时**置灰并附一句说明**（"当前设备/系统不支持动态取色"），比开关点了没反应更好。

**权限 / Windows / 坑**：无需权限；Windows 编译与运行时都正常（返回系统强调色或 null）；⚠️ 桌面取色在用户改系统强调色后需要重启 App 才生效（系统未提供监听）；⚠️ 动态色与 Mconnect 的"透明 scaffold + 自绘背景"组合要人工看一眼对比度（`AppTheme` 的 `scaffoldBackgroundColor: Colors.transparent` + `navigationBarTheme` 全透明是有意为之，见 `app_theme.dart:28-43` 注释）。

## D.2 `url_launcher`（给 W3-B）

- 平台支持：Android SDK 24+、Windows **10+**、Linux/macOS/iOS/Web（[README 支持矩阵](https://raw.githubusercontent.com/flutter/packages/main/packages/url_launcher/url_launcher/README.md)）→ **Windows 不会编译失败**。
- **Android 11(API 30)+ 必须加 `<queries>`**，否则 `canLaunchUrl` 在多数情况下返回 false。本仓库 `AndroidManifest.xml` 现在只有一个 `PROCESS_TEXT` 的 queries（第 108-113 行），需要**在内追加**我们真正会打开的 scheme：

```xml
<queries>
    <!-- 既有：Flutter 引擎的 ProcessTextPlugin -->
    <intent>
        <action android:name="android.intent.action.PROCESS_TEXT"/>
        <data android:mimeType="text/plain"/>
    </intent>
    <!-- 新增：url_launcher 打开浏览器（Last.fm 授权、分享链接、项目主页…） -->
    <intent>
        <action android:name="android.intent.action.VIEW" />
        <data android:scheme="https" />
    </intent>
    <!-- 若还需要邮件反馈 -->
    <intent>
        <action android:name="android.intent.action.VIEW" />
        <data android:scheme="mailto" />
    </intent>
</queries>
```
- **用法约定**（照抄 README）：优先 `launchUrl(uri)` 并处理 false，而不是先 `canLaunchUrl`（README 明确："`canLaunchUrl` can return false even if `launchUrl` would work… it is better to use `launchUrl` directly and handle failure"）。
  ```dart
  Future<void> openExternal(String url) async {
    final uri = Uri.parse(url);
    final ok = await launchUrl(uri, mode: LaunchMode.externalApplication);
    if (!ok) { /* 提示"无法打开链接" */ }
  }
  ```
- **坑**：`file:` 只在桌面可用（Windows 可以，Android 不行），用前 `File.existsSync()`；非 http/https scheme 拼 query 要用 `encodeQueryParameters`（Dart `Uri.queryParameters` 会把空格变 `+`，见 README 的已知 bug 链接）；Last.fm 授权用 `LaunchMode.externalApplication` 才会跳出 App（用 in-app webview 拿不到回跳深链）。
- **权限**：无（`<queries>` 不是权限）。

## D.3 `package_info_plus`（给 W3-C）

**先看硬性要求 vs 本仓库**（[README Requirements](https://raw.githubusercontent.com/fluttercommunity/plus_plugins/main/packages/package_info_plus/package_info_plus/README.md)）：

| Java 17 | `VERSION_17`（`build.gradle.kts:13-20`） | ✅ |

→ **W3-C 动作**：先 `flutter pub add package_info_plus` 后跑一次 `flutter build apk --debug --split-per-abi` 验证。若 AGP 报错，二选一：
1. 把 `android/settings.gradle.kts:22` 的 `com.android.application` 提升到 `8.12.1+`（**会触发全项目 AGP 升级风险，需单独一轮验证 `flutter analyze`+`flutter test`+真机安装**）；
2. 钉住一个能在 AGP 8.11.1 下编译的旧版本（`package_info_plus: <某版本>`），并在 `pubspec.yaml` 写注释说明为何钉版本。
> 该"Requirements"段是插件自己 CI 的开发环境要求，不必然等于消费者的硬门槛——所以是**先验证再决定**，不是先升级。

**Windows 取值**：`PackageInfo.fromPlatform()` 在 Windows 读 exe 的版本资源；本仓库 `windows/runner/Runner.rc:63-73` 用 CMake 注入的 `FLUTTER_VERSION`（兜底字面量 `1.4.4`），`ProductName`/`FileDescription` 都是 **`mconnect`（小写）**。→ 预期 `version == '1.4.4'`、`buildNumber == '15'`、`appName == 'mconnect'`（⚠️ 未在真机/Windows 构建上实测；**若 UI 要用 appName，请勿依赖它的大小写**）。
另注：**不要在 `runApp()` 之前调用** `PackageInfo.fromPlatform()`（README 明示会抛异常：plus_plugins issue #309）；必须在 `WidgetsFlutterBinding.ensureInitialized()` 之后、且在 async 上下文里 await。

**「版本单一来源」怎么做（推荐方案：共存 + 自检，而不是替换）**

现状（不要破坏）：
- 设置页显示 `Text(AppConstants.appVersion)`（`settings_page.dart:749`）；
- `AppConstants.appVersion = 'v1.4.4'`（带 `v` 前缀）还被 `diagnostics_export.dart:123`、`backup_service.dart:23` 使用；
- `test/settings_page_test.dart:63` 用**字面量** `expect(find.text('v1.4.4'), findsOneWidget)` 断言（AGENTS.md §2 故意这么设计：改版本必须同时改测试，当前字面量就是 `v1.4.4`）。

因此**替换成 PackageInfo 会同时打破 3 处语义 + 1 个测试**（`PackageInfo.version` 没有 `v` 前缀，且单测里 `fromPlatform()` 会抛异常，除非 mock）。所以：

**方案 A（推荐，低风险）**：
- 保留 `AppConstants.appVersion` 作为**显示与备份清单**的唯一字面来源（AGENTS.md §2 的同步清单不变）；
- 另加一个 `versionInfoProvider`（`FutureProvider`），把 `PackageInfo` 当**运行期事实**用于：
  - 设置页「版本」副标题下多一行小字（`构建 15 · com.mconnect.mconnect`，用 `buildNumber`/`packageName`）；
  - **一致性自检**：`'v${info.version}' != AppConstants.appVersion` 时，向 `DiagnosticsService` 记一条 warning + 在设置页显示"版本信息不一致（应用内 X / 安装包 Y）"。这正好把 AGENTS.md §2 手工维护的同步规则变成**自动可观测**，而不是靠人记得改七处。

```dart
// lib/core/version/version_info_provider.dart
final packageInfoProvider = FutureProvider<PackageInfo>((ref) => PackageInfo.fromPlatform());

/// 显示用：优先用常量（带 v，测试可控），PackageInfo 只做旁证。
final versionLabelProvider = Provider<String>((ref) => AppConstants.appVersion);

final versionDriftProvider = FutureProvider<String?>((ref) async {
  final info = await ref.watch(packageInfoProvider.future);
  final packaged = 'v${info.version}';
  return packaged == AppConstants.appVersion ? null : '包内 ${AppConstants.appVersion} / 安装包 $packaged';
});
```
- 单测：用 `ProviderScope(overrides: [packageInfoProvider.overrideWith((ref) async => fakeInfo)])`，**不需要**动 `settings_page_test.dart` 的字面量断言。

**方案 B（若确要"彻底单一来源"）**：让显示值来自 `PackageInfo.version`（前缀 `v` 拼接），并把 `AppConstants.appVersion` 降级为"pre-runApp 兜底"；同时必须：
- 给 `settings_page_test.dart` 注入 mock（`PackageInfo.setMockInitialValues(...)` 或 provider override），否则测试会红；
- 更新 AGENTS.md §2 的同步清单（否则文档与实践脱节）；
- 接受 Windows/Android 各自返回值的差异（Windows 读 exe 资源、Android 读 `versionName`）。
→ **本轮的 ROI 与风险比不如方案 A**，除非有明确需求要"安装包与显示 100% 同源"。

**权限 / Windows / 坑**：无权限；Windows 支持 ✅（`installerStore` 恒为 `null`，不要用它做分支）；已知坑：改 `pubspec.yaml` 版本后某些平台需重新构建才生效（iOS 需 Clean build folder，与本仓库无关但不妨记下）。
